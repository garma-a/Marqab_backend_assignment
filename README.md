# حزمة تقييم Backend — استمرارية الإشارات الزمنية

هذه حزمة تقييم مستقلة ومموّهة مستخرجة من نمط عمل Backend قائم. لا تحتوي على واجهة مستخدم، بيانات عملاء، مفاتيح، أسماء منتجات، أو قواعد مجال حقيقية.

المطلوب تنفيذ المهمة داخل هذه الحزمة نفسها. لا تنشئ مشروعًا بديلًا، ولا تغيّر التقنية أو قاعدة البيانات إلا إذا كان التغيير محدودًا ومبررًا في الـPull Request.

## المتطلبات

- Node.js 20 أو أحدث.
- npm.
- Docker مع Docker Compose لتشغيل PostgreSQL 16 الحقيقية.

## التشغيل

```bash
npm ci
npm run db:up
npm run db:migrate
npm run typecheck
npm run test:smoke
npm test
npm run test:db
```

لإيقاف قاعدة البيانات وحذف بيانات التقييم المحلية:

```bash
npm run db:down
```

يستخدم المشروع اتصال PostgreSQL المحلي الموجود في `.env.example` افتراضيًا. إذا غُيّر المضيف أو المنفذ فمرّر الاتصال صراحةً قبل الأوامر، مثل `DATABASE_URL=... npm run db:migrate`، أو صدّر المتغير في جلسة الطرفية.

لا تعدّل `migrations/001_baseline.sql` بعد تشغيلها. ضع تغييرات المخطط في Migration جديدة باسم مثل `002_candidate_fix.sql`. ولإعادة قاعدة التقييم المحلية من الصفر يمكن استخدام `npm run db:reset`.

أمر `npm run verify` يفترض أن PostgreSQL تعمل وأن جميع Migrations مطبقة مسبقًا؛ فهو لا يشغّل الحاوية ولا يغيّر قاعدة البيانات تلقائيًا.

## نقطة البداية

- تعريفات المجال: `src/domain/types.ts`
- المحرك الزمني الحالي: `src/domain/temporal-engine.ts`
- الوصول إلى PostgreSQL: `src/infrastructure/signal-repository.ts`
- تنسيق عملية الإدخال وإعادة التشغيل: `src/application/signal-service.ts`
- المخطط الأولي: `migrations/001_baseline.sql`
- الاختبارات الحسابية: `tests/unit`
- اختبارات PostgreSQL والتزامن: `tests/integration`

`typecheck` و`test:smoke` هما بوابة سلامة الحزمة ويجب أن ينجحا قبل البدء. أما مجموعتا الاختبارات `test` و`test:db` فتحتويان عمدًا اختبارات قبول تكشف النواقص السلوكية المطلوب إصلاحها؛ فشل بعض هذه الاختبارات في النسخة المسلّمة ليس عطل إعداد.

حالة الاختبارات قبل التعديل جزء من التسليم؛ وثّقها ولا تحذف أي اختبار. يجوز تعديل الاختبارات أو إضافة اختبارات جديدة لتوضيح السلوك، لكن لا يجوز إضعاف معايير القبول أو تحويل اختبار فاشل إلى `skip`/`todo`.

اقرأ `TASK.md` كاملًا قبل البدء، واكتب ملخص التسليم في `IMPLEMENTATION_NOTES.md`.
